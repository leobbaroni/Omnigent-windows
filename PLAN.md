# PLAN.md — Omnigent for Windows

Track: from scratch on top of a vendored base. Walk a skeleton (the vendored
shell builds and runs on Windows) through the riskiest unknown first (CLI
discovery + bootstrap on a machine without Omnigent), then layer native
integration, updates, packaging, tests, docs.

Crew: single model (this session) for all phases; Tier-1 self-review after each
phase; a Tier-2 adversarial review wave is offered to the user at the end.

## Phase 0 — Planning artifacts ✅
Done when: `COMPAT.md`, `SPEC.md`, `PLAN.md`, `CONTEXT.md`, `docs/adr/0001` committed.

## Phase 1 — Skeleton: vendor and run the upstream shell on Windows ✅
1. `upstream.lock.json` + `scripts/sync-upstream.mjs` (copy `web/electron` into `app/`, excluding mac-only signing assets; build overlay + server-selector-v2 from upstream `web/`; report drift vs `app/src/win/`).
2. `app/package.json`: Windows build config (nsis assisted + portable, github publish), version, scripts.
3. Install deps with corepack pnpm; run upstream unit tests (`node --test`).
4. Launch `electron .` on this machine: the setup page appears (no Omnigent); screenshot.
Done when: `corepack pnpm --dir app test` is green and the app window opens showing the setup page.

## Phase 2 — Riskiest unknown: Windows CLI discovery + bootstrap (R1–R4, R17) ✅
1. `app/src/win/cli_windows.js`: candidate paths (`.exe`, uv tool bin dir), `where`, WSL probe; hook into `omnigent_cli.js` (`candidatePaths`, `INSTALL_COMMAND`, `windowsHide`, UTF-8 env).
2. `app/src/win/bootstrap.js`: prerequisite detection (python, uv, node, wsl), command catalog, guarded install runner (dialog, then visible PowerShell).
3. Setup page: Windows bootstrap panel (`app/setup/win-bootstrap.js` + markup), wired via `omnigentSetup.win*` IPC (setup page only).
4. `app/src/win/compat.js`: version range + one-time warning.
Done when: unit tests for cli_windows/bootstrap/compat pass; manual: the app shows the bootstrap panel with correct detections on this machine (uv 0.12.7, Python 3.13, Node 22, no Omnigent).

## Phase 3 — Native Windows integration (R5–R7, R9–R14) ✅
1. `app/src/win/logger.js` (rotating file log; console capture), first, so the rest logs.
2. `app/src/win/tray.js` (icon, menu, status line, actions), close-to-tray + quit semantics via `main.js` hooks.
3. `app/src/win/badge.js` (overlay icon PNGs generated by `scripts/gen-badges.mjs`, `setOverlayIcon`).
4. `app/src/win/startup.js` (login item).
5. Owned-server heartbeat + crash surfacing (`server_manager` hook).
6. Deep-link verification on Windows.
Done when: unit tests pass; manual: tray menu works, close hides, Quit exits, badge overlay shows on `setBadgeCount(3)`.

## Phase 4 — WSL backend + settings page (R8, R18) ✅
1. `app/src/win/wsl.js` (distro list, command wrapper, status via CLI).
2. `app/settings-win/index.html` + preload; IPC gated to the bundled page; tray → Settings.
Done when: unit tests; settings persist and reload; WSL mode constructs the correct argv (manual WSL test documented as skipped if no distro has Omnigent).

## Phase 5 — Updates (R15–R16) ✅
1. `app/package.json` publish → github; updater settings surfaced in the settings page; portable build disables updates.
2. Omnigent update check + guided upgrade (`omni upgrade --check`; dialog, then console).
Done when: unit tests; manual `omni upgrade --check` path exercised (after the Phase 6 install).

## Phase 6 — Test against a real installation ✅
1. `uv tool install --python 3.12 omnigent==0.12.0` (reversible; announced in the log).
2. Walk the manual test matrix in README (first launch, start/stop/restart, existing server, crash recovery, notifications, badge, tray, multi-window, multi-server via a second foreground server, deep link, OAuth popup smoke, file drag/drop, external links).
3. Playwright-Electron smoke (`app/e2e/win_smoke.e2e.js`) against the real server.
Done when: results recorded in `PROJECT_LOG.md` and the parity report; COMPAT §15 updated with the tested version.

## Phase 7 — Packaging, CI, docs ✅
1. `corepack pnpm --dir app build:win` → NSIS + portable in `app/dist/`; install/uninstall smoke on this machine.
2. `.github/workflows/build-windows.yml`, `release.yml` (tags → release + `latest.yml`), signing hooks documented.
3. `README.md`, `ARCHITECTURE.md`, final `COMPAT.md` pass, feature-parity report (`PARITY.md`).
Done when: the installer installs and launches; workflows parse as YAML; docs complete.

## Risks & Landmines

- Console windows flashing on every CLI call (missing `windowsHide`): fixed in the Phase 2 hook, verified visually.
- `TerminateProcess` on the host child may orphan runners: verify in Phase 6; document; Job Objects on the Python side mitigate.
- Unsigned installer: SmartScreen warning; documented; signing env hooks ready.
- Native-Windows host has no terminals: surfaced in the bootstrap and README, not hidden.
- Upstream drift: all Windows code under `app/src/win/`; hooks marked `// [win]`.
